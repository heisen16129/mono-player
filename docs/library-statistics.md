# 歌手和目录统计

`read_library_statistics` 从 SQLite 曲库读取歌曲，在 Rust 中完成歌手分组、各组歌曲数与总时长、目录匹配和目录歌曲数统计。前端传入当前目录设置、搜索词和未知歌手的显示名称，不上传歌曲列表。

- 合作歌曲分别计入各位歌手，歌手页总歌曲数沿用各分组数量之和。
- 搜索匹配歌曲标题和歌手，歌手分组随搜索变化。
- 目录卡片显示目录全部歌曲数，包含子目录；相似名称的其他目录不混入。重叠目录分别计数，总数仍按目录数量相加。
- 目录响应同时包含搜索后的歌曲、数量和总时长，供目录详情展示；空目录不显示。
- 曲库加载、扫描、目录变更、歌曲元数据更新及搜索变化会重新查询。前端合并短时间内的请求，并忽略过期响应。
- 中文名称排序、分钟显示格式和卡片配色仍由前端处理，不在前端重新分组或累计目录歌曲数。

验证：`cargo test --manifest-path src-tauri/Cargo.toml library_statistics --lib` 和 `node --test scripts/library-statistics.test.mjs`。

歌手排序由 SQL 完成：歌曲数降序、歌手名升序；歌手内歌曲按标题升序。使用 SQLite NOCASE 排序（ASCII 不区分大小写，中文不采用拼音排序），并以原始名称、标题及曲目索引稳定排序。
