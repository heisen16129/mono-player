# 歌词渲染插件系统执行计划

## 目标

将歌词页渲染层从播放器宿主抽离为可切换插件，同时保留现有 WASM 歌词来源插件和 Rust 歌词解析。当前已实现内置渲染插件、外置 JavaScript sandbox 渲染器、本地 manifest 安装、插件选择和插件设置；插件市场分发与细粒度权限代理仍后置。

## 架构边界

```text
WASM 音源/歌词插件 -> TrackLyrics -> Rust 歌词解析 -> 歌词渲染插件
```

- 来源插件继续负责搜索、获取、翻译和补全歌词。
- Rust 继续输出标准化 `LyricLine[]`。
- 渲染插件负责 DOM/CSS、滚动、逐字高亮、Canvas、WebGL 和布局。
- 宿主负责生命周期、播放时钟、播放状态、跳转、错误回退和全局歌词操作。
- 通用设置留在播放器设置；渲染插件设置使用插件配置存储。

#### 完整引擎与桥接边界

```text
Mono LyricsRendererContext
  -> context-adapter.mjs（Track / lyrics / config）
  -> renderer.mjs（mount / update / destroy）
  -> Mineradio engine（WebGL / shader / camera / stage lyrics）

Mineradio controls
  -> sandbox action message
  -> Mono playback / queue / volume actions
```

“完整引擎”指 Mineradio 的播放视觉运行时，不代表复制整个 Mineradio 产品。登录、搜索、天气电台、3D 歌单架、摄像头手势和桌面歌词副窗口没有进入插件；宿主 sandbox 也不允许插件直接访问音频元素和文件系统。

当前宿主只提供 5 段后端频谱，原版使用 1024 个 FFT bin，因此频率细节和离线节拍分析不能做到逐样本一致。这是外置插件方案的主要效果限制；其余封面、歌词、预设和控制状态均通过统一数据模型传递。

```text
[Mineradio 歌词][播放控制] 发起切换请求
[歌词插件宿主][播放控制] 已接收
[歌词插件宿主][播放控制] 执行完成
[歌词插件通信桥][播放控制] 执行结果
[Mineradio 歌词][播放控制] 状态更新
```

Apple Music 的插件日志前缀为 `[Apple Music 歌词][播放控制]`，宿主和桥接日志相同。“发起切换请求”“已接收”“执行完成”“执行结果”使用同一个请求编号。

- 没有“指针按下”：按钮被其他层遮挡，或指针没有命中按钮。
- 有“指针按下”、没有“发起切换请求”：不是主指针或鼠标左键操作。
- 有“发起切换请求”、没有“已接收”：iframe 到宿主的消息没有送达。
- 有“已接收”、没有“执行完成”或“执行失败”：播放器控制调用没有结束。
- 有“执行完成”、没有后续“状态更新”：播放器状态没有同步回歌词插件。
- 同一请求编号出现多次“已接收”：一次操作被重复发送。
