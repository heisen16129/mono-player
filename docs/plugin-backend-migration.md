# 插件管理后端迁移

执行顺序与验收：
1. 安装管理：本地 WASM/JSON、商城安装和更新由后端按 ID 提交，保留配置和主题关联。
2. 启用停用：按 ID 保存，后端协调音箱服务。
3. 配置：后端规范化、校验、默认值合并。
4. 订阅目录：后端增删、缓存、刷新、合并和逐来源错误。
5. 商城状态：后端比较安装版本与目录版本。
6. 批量操作：后端循环执行，事件进度及逐项结果。
7. 清理回归：移除旧入口，验证构建、测试和重启数据保留。

状态：以上功能已接入，构建与自动化回归通过。真实商城安装和应用重启需要在运行中的桌面应用验证。

接口：
- `plugin_list`：后端返回规范化清单，可包含合并默认值后的有效配置。
- `plugin_action`：安装、更新、卸载、启停、排序；排序只提交 ID，不覆盖插件字段。
- `plugin_batch`：逐项执行，返回成功/失败原因；`plugins://batch` 推送带请求 ID 的进度。
- `plugin_catalog`：查询快照、添加/删除订阅、刷新单个或全部来源。返回订阅、合并目录、官方目录、版本状态、删除标记和逐来源错误。
- `plugin_config_get/set`：统一清理配置、合并默认值，保存时校验字段类型、必填项及数值范围；保存直接返回有效配置。

数据规则：
- 保留现有安装记录、配置和订阅。旧目录缓存按来源归入 `plugins.catalog.sources`；无法识别来源的旧缓存保留在 legacy 分组。
- 同 ID 按官方目录、订阅顺序合并，后面的来源覆盖前面的来源；结果按名称和 ID 稳定排序。
- 来源刷新失败保留其上次成功缓存；刷新成功会替换整个来源结果，因此已从来源撤下的条目不会永久追加残留。
- 版本状态延续原规则：未安装为 available、版本不同为 update、版本相同为 installed，不额外引入语义版本升级规则。
- 更新保留插件的启用状态及配置；主题插件继续由后端维护主题关联。
- 前端保留表单输入、筛选、拖动交互和展示。旧整表保存、清单构建等单独命令已移除。

验证覆盖安装记录替换与配置保留、配置默认值及越界、旧缓存来源隔离、市场状态、批量进度隔离和失败清理。
