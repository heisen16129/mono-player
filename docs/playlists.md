# 歌单存储

歌单保存于 `music-player.sqlite` 的 `playlists` 和 `playlist_tracks` 表，不读取、不迁移旧设置 JSON 中的歌单。启动时在初始化数据库后、启动服务前，删除旧 JSON 的 `mono-player-settings.playlists` 字段并写回文件；其他设置保留，没有该字段时不重写文件。

- 歌单名称由后端去除首尾空白并校验非空、唯一，ID 由后端生成。
- 歌曲条目保存身份键、本地曲库关联、完整歌曲快照和排序位置。支持本地与在线歌曲混合添加，同一歌单按身份去重，不同歌单独立。
- 在线歌曲保留音源插件 ID、来源歌曲 ID、封面和 `sourceRaw` 等解析数据，播放仍通过现有音源解析流程；不以临时 URL 作为具备完整来源标识的歌曲身份。
- 创建时保留传入顺序，后续新增歌曲置顶，重复添加不改变原有顺序。
- 创建和批量编辑使用事务。删除歌单级联删除条目，不删除歌曲文件、曲库记录或收藏。
- 移除曲库目录时一并删除所有歌单内对应的本地歌曲及快照，保留在线歌曲、其他目录歌曲和空歌单。
- 前端独立维护只读歌单视图，不再把歌单写入设置。后端写入成功后更新界面，失败保留原状态并提示。
- 小爱音箱和 MCP 从同一数据库读取，音箱歌单编辑也调用同一数据层。

验证：`node --test scripts/playlists.test.mjs scripts/favorites.test.mjs` 和 `cargo test --manifest-path src-tauri/Cargo.toml database:: --lib`。
