# 前端业务收敛计划

1. 收藏与歌单使用后端返回的最新歌曲信息。
2. 移除目录统一使用后端队列清理和会话保存。
3. 后端统一播放列表校验和去重。
4. 后端按用途查询插件。
5. 托盘状态和播放操作由后端处理。
6. 下载列表和歌曲下载标记从同一后端快照返回。

每项检查调用链，完成后运行相关自动化测试和前端构建。

## 完成情况

六项已接入：
- 收藏、歌单复用已有数据库查询的最新曲库信息，删除前端二次合并；曲库更新仍触发重新查询。
- 目录删除复用后端 `remove_library_queue_sources`，后端保存会话并推送队列；前端只应用快照。即使队列不为空，当前歌曲被删除也清空播放栏。
- 后端队列统一过滤不可播放来源和按身份去重。本地路径忽略大小写，在线 URL 保留大小写，插件歌曲按来源身份区分。删除前端队列去重及相关参数。
- `plugin_list` 增加 purpose 查询：music-search、lyrics-search、desktop-lyrics。搜索来源保留 enabled 字段，保持原有禁用状态显示；桌面歌词仅返回启用项。
- 托盘通过 `tray_snapshot` 查询后端状态；暂停、恢复、上一首、下一首、播放模式直接在后端执行。仅打开设置页仍通知主界面。删除前端托盘状态持久化及播放操作转发。
- `download_records_snapshot` 在同一数据库锁内返回已下载列表、下载中列表、已下载标记、处理中标记，替代两次列表查询和前端状态过滤。

验证：前端构建，收藏/歌单/启动/恢复播放/下载/队列快照回归，以及 Rust 单元测试。桌面托盘和真实音频设备尚未手动联调。
